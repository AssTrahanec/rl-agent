# План улучшения результатов

## Текущая ситуация

- Агент (baseline): Sharpe 1,80, доходность +64%, просадка 18%
- Ансамбль: Sharpe 2,63, доходность +88%, просадка 12%
- Buy & Hold: Sharpe 1,68, доходность +112%, просадка 26%
- **Проблема:** доходность агента ниже рынка
- **Проблема:** текстовая информация не помогает на дневном интервале

## Варианты улучшений (по приоритету: impact / effort)

### 1. Изменить функцию награды (ВЫСОКИЙ приоритет, 30 мин кода + 45 мин обучения)

**Сейчас:** `reward = log_return × allocation - tx_cost × |Δallocation|`

Агент получает награду за любой рост рынка. Ему нет стимула обгонять рынок — достаточно просто быть в позиции.

**Варианты из литературы:**

а) **Differential Sharpe Ratio** (Moody & Saffell, NeurIPS) — классический подход, системы с DSR обгоняют S&P 500 на 25-летнем тесте. Награда = изменение скользящего Sharpe за последние N шагов.

б) **Composite reward** (arxiv 2506.04358, 2024) — линейная комбинация: return + volatility penalty + drawdown penalty. Превосходит single-metric reward по Sharpe.

в) **Benchmark-relative reward** — `reward = agent_return - market_return`. Агент получает награду только за то, что обогнал рынок.

**Что менять:** одну строку в `src/env/trading_env.py` (строка 56).

**Рекомендуемый вариант:** начать с (в) как самого простого, потом попробовать (а).

### 2. Разрешить короткие позиции (ВЫСОКИЙ приоритет, 15 мин кода)

**Сейчас:** allocation ∈ [0, 1] — агент может только покупать.

**Изменение:** allocation ∈ [-1, 1]. При allocation < 0 агент зарабатывает на падении рынка.

**Что менять:** `action_space` в `src/env/trading_env.py` (строка 36) и формулу reward (строка 56 — уже поддерживает отрицательные allocation).

**Ожидаемый эффект:** на падающем рынке 2025 Q1 агент мог бы заработать вместо потерь.

### 3. Walk-forward переобучение (ВЫСОКИЙ приоритет, 45 мин обучения)

**Сейчас:** обучение 2020–2023, тест 2024. Модель не адаптируется.

**Из литературы:** UCL Recurrent RL Crypto Agent с walk-forward дал total return 350% за 5 лет, information ratio 1,46. Без переобучения performance деградирует.

**Скрипт уже написан:** `scripts/run_walkforward.py`. Нужно только запустить на реальных данных.

**Схема:** train 2 года → test 3 месяца → сдвиг на 3 месяца → повторить.

### 4. Улучшить обработку новостей (СРЕДНИЙ приоритет, 1-2 часа)

**Сейчас:** среднее sentiment за день. Теряется информация о значимости отдельных новостей.

**Варианты:**

а) **Weighted sentiment** — вместо среднего использовать максимальное абсолютное значение (экстремальные новости важнее).

б) **Sentiment delta** — добавить изменение тональности как признак (резкий сдвиг = сигнал).

в) **Event-driven switching** (arxiv 2402.01441, 2024) — переключение стратегий при обнаружении значимого сдвига в тональности. Результат в статье: annualized return 18,36%, лучший Sharpe и Sortino среди всех стратегий.

г) **Fine-tuned FinBERT** — модель `burakutf/finetuned-finbert-crypto` на HuggingFace, обученная на крипто-текстах. Или дообучить самим (код есть: `src/features/finetune_finbert.py`). По статье (arxiv 2411.12748): fine-tuned FinBERT + BiLSTM дал ~98% accuracy для BTC.

### 5. LSTM вместо MLP (СРЕДНИЙ приоритет, 2-3 часа)

**Сейчас:** MLP [256, 256]. Видит окно как плоский вектор.

**Из литературы:** Cascaded LSTM-PPO превосходит MLP-PPO на 4 фондовых индексах (Expert Systems with Applications, 2024). LSTM лучше захватывает временные зависимости.

**Реализация:** `RecurrentPPO` из `sb3-contrib` — drop-in замена для PPO.

```
pip install sb3-contrib
from sb3_contrib import RecurrentPPO
```

**Ожидаемый эффект:** +10–30% по Sharpe (по литературе).

### 6. Смешанный ансамбль PPO + A2C (НИЗКИЙ приоритет, 30 мин)

**Сейчас:** ансамбль из 3 PPO моделей.

**Идея:** добавить A2C модели (Sharpe 1,86, std 0,12 — стабильнее PPO). Разные алгоритмы делают разные ошибки → ансамбль устойчивее.

**Код ансамбля уже поддерживает разные модели** (`src/eval/ensemble_backtest.py`).

### Этап 1: быстрые улучшения (1-2 часа)

1. Изменить reward на benchmark-relative
2. Разрешить шорт [-1, 1]
3. Обучить 3 seeds × 2 варианта (новый reward; новый reward + шорт)
4. Сравнить с текущими результатами

5. Запустить `run_walkforward.py` на реальных данных
6. Показать, что модель адаптируется к смене режима рынка

### Этап 3: NLP улучшения (2-3 часа)

7. Заменить mean sentiment на max absolute + добавить sentiment delta

9. Переобучить Agent-2 и сравнить

### Этап 4 (если есть время): архитектура

10. Попробовать RecurrentPPO (LSTM)

## Что это даст для тезиса

Каждое улучшение — это дополнительный эксперимент и строчка в таблице результатов:

- **Reward shaping** → «модификация функции награды повысила доходность на X%»
- **Короткие позиции** → «расширение пространства действий позволило агенту зарабатывать на снижении рынка»
- **Walk-forward** → «скользящее переобучение подтвердило адаптивность модели»
- **Fine-tuned FinBERT** → «дообучение языковой модели на криптовалютных текстах сделало тональность полезным признаком»
- **LSTM** → «рекуррентная архитектура улучшила захват временных зависимостей»

Даже один-два улучшения существенно укрепят работу.
