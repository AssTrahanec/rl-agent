## 0. Словарь терминов

Если встречаешь незнакомое слово в тексте — ищи здесь.

### Алгоритмы обучения с подкреплением

| Аббревиатура | Полное название | Что это |
|---|---|---|
| **RL** | Reinforcement Learning | Обучение с подкреплением — программа учится сама, пробуя действия и получая награду или штраф. Нет готовых правильных ответов |
| **PPO** | Proximal Policy Optimization | Алгоритм RL. "Проксимальная оптимизация политики" — обновляет стратегию маленькими шагами, чтобы не сломать то, что уже работало |
| **A2C** | Advantage Actor-Critic | Алгоритм RL. Два компонента: Actor (принимает решения) и Critic (оценивает насколько решение было хорошим). A2C — синхронная версия |
| **SAC** | Soft Actor-Critic | Алгоритм RL. Похож на A2C, но дополнительно поощряет "случайность" в действиях — это помогает лучше исследовать варианты |
| **SB3** | Stable-Baselines3 | Готовая Python-библиотека с реализациями PPO/A2C/SAC. Не надо писать алгоритмы с нуля — просто вызываешь `PPO.learn()` |

### Нейросети и ML

| Аббревиатура | Полное название | Что это |
|---|---|---|
| **MLP** | Multi-Layer Perceptron | Многослойный перцептрон — "классическая" нейросеть из нескольких слоёв. Входные данные → скрытые слои → выходное число |
| **NLP** | Natural Language Processing | Обработка естественного языка — раздел AI, который работает с текстом. FinBERT и MiniLM — примеры NLP-моделей |
| **BERT** | Bidirectional Encoder Representations from Transformers | Тип нейросети для текста. Читает предложение сразу в обоих направлениях (не слева-направо, а целиком), поэтому лучше понимает контекст |
| **FinBERT** | Financial BERT | BERT, дообученный на финансовых текстах (отчёты, новости). Понимает специфику "рынок упал", "прибыль выросла" лучше обычного BERT |
| **PCA** | Principal Component Analysis | Метод сжатия данных. Из 384 чисел-признаков делает 32, сохраняя главную информацию и выбрасывая повторяющуюся |
| **GAE** | Generalized Advantage Estimation | Метод вычисления "насколько действие было лучше среднего". Параметр λ балансирует точность и стабильность этой оценки |

### Технические индикаторы

| Аббревиатура | Полное название | Что это |
|---|---|---|
| **OHLCV** | Open, High, Low, Close, Volume | Стандартный набор данных свечи: цена открытия, максимум, минимум, закрытия, и объём торгов за день |
| **SMA** | Simple Moving Average | Простая скользящая средняя — среднее цены за последние N дней. Обновляется каждый день (окно "скользит") |
| **EMA** | Exponential Moving Average | Экспоненциальная скользящая средняя — как SMA, но последние дни важнее старых (больший вес) |
| **MACD** | Moving Average Convergence Divergence | "Схождение-расхождение скользящих средних" — разница между быстрой и медленной EMA. Показывает силу тренда |
| **RSI** | Relative Strength Index | Индекс относительной силы — число 0-100: выше 70 = рынок перегрет (скоро может упасть), ниже 30 = перепродан (скоро может вырасти) |
| **ATR** | Average True Range | Средний истинный диапазон — насколько в среднем цена двигается за день. Мера волатильности: большой ATR = рынок дёргается сильно |
| **OBV** | On-Balance Volume | Индикатор накопленного объёма — если цена растёт на большом объёме, значит покупателей много и тренд сильный |
| **BB** | Bollinger Bands | Полосы Боллинджера — коридор вокруг средней цены. Если цена выходит за полосу, это сигнал что что-то необычное происходит |

### Прочие термины

| Слово/аббревиатура | Что это |
|---|---|
| **Ablation study** | Научный эксперимент: берёшь модель, убираешь один компонент, смотришь как ухудшится результат. Так доказывают что каждая часть нужна |
| **Embedding** | Вектор чисел (например 384 числа), который кодирует смысл текста. Похожие по смыслу тексты → похожие векторы |
| **Sentiment** | Тональность текста: положительная (+1), отрицательная (-1) или нейтральная (0). "Bitcoin растёт" → позитивный sentiment |
| **Backtest** | Проверка стратегии на исторических данных. Обучили на 2020-2023, проверяем на 2024 — видим как бы работало в прошлом |
| **Sharpe ratio** | Метрика качества стратегии: доходность делённая на риск. Выше = лучше. > 1 хорошо, > 2 отлично |
| **Sortino ratio** | Как Sharpe, но штрафует только за убыточные дни (а не за любые колебания) |
| **Max Drawdown (MDD)** | Максимальная просадка — на сколько процентов упал портфель от максимума до минимума за всё время |
| **Calmar ratio** | Годовая доходность делённая на максимальную просадку. Показывает: стоит ли риск результата |
| **Bootstrap CI** | Метод статистики: перемешиваешь результаты тысячи раз случайно, смотришь в каком диапазоне обычно оказывается среднее. Так находят доверительный интервал (CI = Confidence Interval) |
| **Парquet** | Формат файла для таблиц. В 5-10 раз компактнее CSV, в 100 раз быстрее читается |
| **Epoch** | Один проход по всем обучающим данным. В PPO — сколько раз пересмотреть собранный опыт перед следующим шагом |
| **Policy** | Стратегия агента: функция, которая по наблюдению (цены) выдаёт действие (сколько вложить) |
| **UTC** | Coordinated Universal Time — мировое стандартное время (Москва = UTC+3). Используем чтобы даты в разных источниках совпадали |
| **RNG** | Random Number Generator — генератор случайных чисел. Фиксируем seed (начальное значение) чтобы результаты были воспроизводимы |
| **Z-score** | Стандартизированное значение: `(x - среднее) / отклонение`. Показывает на сколько стандартных отклонений точка отличается от нормы |
| **Data leakage** | Утечка данных — ошибка когда модель "видит будущее" при обучении. Например нормализация по всем данным включая тестовый период |
| **Lazy loading** | Ленивая загрузка — загружаем ресурс (например модель) только в момент первого использования, а не при старте программы |

## 1. Общая идея проекта

Мы учим компьютерную программу торговать Bitcoin. Используем **Reinforcement Learning (RL)** — обучение с подкреплением.

### Аналогия с собакой

Ты учишь собаку команде "сидеть". Если она села — лакомство. Если нет — ничего. Со временем она понимает: эта команда → лакомство.

В нашем проекте:
- **Собака** = агент (нейросеть)
- **Ситуация** = цены и индикаторы за 30 дней
- **Действие** = сколько денег вложить в BTC (от 0% до 100%)
- **Лакомство** = прибыль. Вложился и цена выросла → награда

### Три версии агента (ablation study)

Делаем три версии чтобы понять — **помогают ли новости**?

| Агент | Что видит | Фичей |
|-------|-----------|-------|
| Agent-1 Baseline | только цены и индикаторы | 20 |
| Agent-2 Sentiment | + "хорошие/плохие" новости | 21 |
| Agent-3 Embeddings | + "смысл" новостей | 52 |

## 2. src/data/price_collector.py

**Задача:** скачать исторические цены BTC и ETH с биржи Binance.

```python
# строки 1–5
import ccxt          # библиотека-переводчик для 100+ бирж
import pandas as pd  # работа с таблицами
import logging       # логи вместо print

logger = logging.getLogger(__name__)
# __name__ = "src.data.price_collector" — имя этого модуля в логах
```

> **Зачем ccxt?** У каждой биржи своё API (Application Programming Interface — интерфейс для общения программ между собой). ccxt — один код для 100+ бирж, иначе пришлось бы для каждой биржи писать отдельный код.

```python
# строка 8
def fetch_ohlcv(symbol: str, start: str, end: str, exchange_id: str = "binance") -> pd.DataFrame:
```

> `fetch_ohlcv` = скачать **OHLCV** (Open, High, Low, Close, Volume — цены открытия/максимум/минимум/закрытия и объём торгов за день).
> Параметры: торговая пара (`"BTC/USDT"`), даты начала/конца, название биржи.

```python
# строка 10
exchange = getattr(ccxt, exchange_id)()
```

> `getattr(ccxt, "binance")` — берём класс по имени как строке. `()` — создаём объект.
> Зачем так: биржу можно менять через параметр, не переписывая код.

```python
# строки 11–12
since = exchange.parse8601(f"{start}T00:00:00Z")
end_ts = exchange.parse8601(f"{end}T00:00:00Z")
```

> Конвертируем `"2020-01-01"` → `1577836800000` (миллисекунды с 1970 года).
> Binance принимает только такой формат. `T00:00:00Z` = полночь UTC.

```python
# строки 15–20
while since < end_ts:
    ohlcv = exchange.fetch_ohlcv(symbol, "1d", since=since, limit=500)
    if not ohlcv:
        break
    all_data.extend(ohlcv)
    since = ohlcv[-1][0] + 86400000  # следующий день
```

> **Почему цикл, а не один запрос?** Binance отдаёт максимум 500 свечей за запрос.
> У нас 1827 дней — нужно минимум 4 запроса.
> `ohlcv[-1][0]` — timestamp последней свечи. `86400000` = 1 день в миллисекундах.

```python
# строка 22
df = pd.DataFrame(all_data, columns=["timestamp", "open", "high", "low", "close", "volume"])
```

> Каждая свеча = список `[timestamp, open, high, low, close, volume]`.
> Превращаем список таких списков в таблицу с именами колонок.

```python
# строка 23
df["timestamp"] = pd.to_datetime(df["timestamp"], unit="ms", utc=True)
```

> Конвертируем `1577836800000` → `2020-01-01 00:00:00 UTC`. `unit="ms"` = миллисекунды.

```python
# строка 24
df = df.set_index("timestamp").sort_index()
```

> Дата становится **индексом** таблицы (вместо 0, 1, 2...). Сортируем по дате.

```python
# строки 25–26
df = df[df.index <= pd.Timestamp(end, tz="UTC")]
df = df[~df.index.duplicated(keep="first")]
```

> Строка 25: обрезаем дни после даты `end`.
> Строка 26: убираем дубликаты — на стыке запросов одна дата может прийти дважды.
> `~` = НЕ, `duplicated()` = маска дублей, оставляем первое вхождение.

## 3. src/features/technical.py

**Задача:** из сырых цен вычислить ~20 технических индикаторов.

> **Зачем нужны индикаторы?** Цена 40,000 сама по себе ничего не говорит.
> Технические индикаторы — математические формулы применённые к ценам. Они "переваривают" данные в более понятный сигнал: тренд (куда движется), перекупленность (не слишком ли сильно выросло), объём (сколько людей участвует).

```python
# строки 13–17
df = df.copy()       # работаем с копией, не меняем оригинал
close = df["close"]  # цены закрытия — основа большинства формул
high = df["high"]
low = df["low"]
volume = df["volume"]
```

### SMA — простая скользящая средняя (Simple Moving Average)

```python
# строки 20–21
df["sma_7"] = close.rolling(7).mean()
df["sma_25"] = close.rolling(25).mean()
```

> `rolling(7)` = окно из 7 последних дней. `.mean()` = среднее.
> Зачем две SMA (7 и 25)? Когда быстрая (7 дней) пересекает медленную (25 дней) снизу вверх — это классический сигнал начала роста. Называется "золотой крест".

### EMA — экспоненциальная средняя (Exponential Moving Average)

```python
# строки 22–23
df["ema_12"] = close.ewm(span=12, adjust=False).mean()
df["ema_26"] = close.ewm(span=26, adjust=False).mean()
```

> Как SMA, но последние дни весят **больше**. `α = 2/(12+1) ≈ 0.15`.
> Сегодня вносит 15%, вчерашняя EMA — 85%. Это делает EMA "реактивнее" — она быстрее замечает разворот тренда.
> `adjust=False` = рекурсивная формула (каждое значение зависит от предыдущего — стандарт трейдинга).

### MACD (Moving Average Convergence Divergence — схождение/расхождение скользящих средних)

```python
# строки 26–28
df["macd"] = df["ema_12"] - df["ema_26"]
df["macd_signal"] = df["macd"].ewm(span=9, adjust=False).mean()
df["macd_hist"] = df["macd"] - df["macd_signal"]
```

> `macd` — разница между быстрой (12 дней) и медленной (26 дней) EMA. Положительный = быстрая выше медленной = тренд вверх.
> `macd_signal` — сглаженный MACD (EMA от самого MACD). Своего рода "средняя от средних".
> `macd_hist` — гистограмма: расстояние между MACD и его сигнальной линией. Если растёт и положительная = тренд усиливается.

### RSI (Relative Strength Index — индекс относительной силы)

```python
# строки 31–37
delta = close.diff()            # цена сегодня минус вчера
gain = delta.clip(lower=0)      # только дни роста
loss = (-delta).clip(lower=0)   # только дни падения (берём модуль)
avg_gain = gain.ewm(com=13, adjust=False).mean()
avg_loss = loss.ewm(com=13, adjust=False).mean()
rs = avg_gain / avg_loss.replace(0, np.nan)
df["rsi_14"] = 100 - (100 / (1 + rs))
```

> RSI — число от 0 до 100. Показывает "усталость" рынка: как много было роста по сравнению с падением за последние 14 дней.
> RSI > 70 = рынок **перекуплен** (росло слишком быстро, скоро может откатиться).
> RSI < 30 = рынок **перепродан** (падало слишком быстро, скоро может отскочить).
> `com=13` = параметр сглаживания по стандарту Wilder (изобретатель RSI): `com = span - 1`, span=14.
> `.replace(0, np.nan)` = защита от деления на ноль (если за 14 дней не было ни одного дня падения).

### Bollinger Bands (BB — полосы Боллинджера)

```python
# строки 40–45
sma_20 = close.rolling(20).mean()
std_20 = close.rolling(20).std()
df["bb_upper"] = sma_20 + 2 * std_20
df["bb_lower"] = sma_20 - 2 * std_20
df["bb_mid"] = sma_20
df["bb_width"] = (df["bb_upper"] - df["bb_lower"]) / df["bb_mid"]
```

> "Коридор" вокруг средней цены шириной ±2 **стандартных отклонения** (std — мера разброса: чем больше, тем сильнее цена "прыгает").
> По статистике 95% цен должны быть внутри. Цена вышла за верхнюю полосу = перекуплена.
> `bb_width` — относительная ширина коридора. Когда полосы **сужаются** (рынок спокойный) → часто после этого следует резкое движение.

### ATR (Average True Range — средний истинный диапазон)

```python
# строки 48–52
tr1 = high - low                        # внутридневной размах
tr2 = (high - close.shift()).abs()      # гэп вверх от вчерашней цены
tr3 = (low - close.shift()).abs()       # гэп вниз от вчерашней цены
tr = pd.concat([tr1, tr2, tr3], axis=1).max(axis=1)
df["atr_14"] = tr.ewm(com=13, adjust=False).mean()
```

> `close.shift()` = вчерашняя цена закрытия. Берём максимум из трёх вариантов —
> учитываем ночные **гэпы** (gap — разрыв: цена сегодня открылась далеко от вчерашнего закрытия из-за новостей за ночь).
> Показывает: "насколько BTC обычно движется за день" = мера **волатильности** (нестабильности цены).
> Пример: ATR = 2000$ → в среднем за день BTC двигается на 2000 долларов.

### OBV (On-Balance Volume — объём нарастающим итогом)

```python
# строки 55–56
direction = np.sign(close.diff()).fillna(0)  # +1 рост, -1 падение
df["obv"] = (direction * volume).cumsum()
```

> Идея: если цена выросла сегодня — прибавляем дневной объём к счётчику. Если упала — вычитаем.
> Растём на большом объёме = много людей покупает = тренд настоящий и сильный.
> Растём на маленьком объёме = мало участников = тренд может быть ненастоящим.
> `cumsum()` = нарастающий итог (складывает все значения от начала).

### Stochastic

```python
# строки 59–63
lowest_low = low.rolling(14).min()
highest_high = high.rolling(14).max()
denom = (highest_high - lowest_low).replace(0, np.nan)
df["stoch_k"] = 100 * (close - lowest_low) / denom
df["stoch_d"] = df["stoch_k"].rolling(3).mean()
```

> Где текущая цена относительно диапазона за 14 дней?
> 100% = на максимуме, 0% = на минимуме.
> `stoch_d` — сглаженная версия (3-дневное среднее от `%K`).

### Returns

```python
# строки 66–67
df["return_1d"] = close.pct_change()
df["return_5d"] = close.pct_change(5)
```

> `pct_change()` = `(сегодня - вчера) / вчера`. Было 100, стало 105 → 0.05 (5%).

## 4. src/features/normalizer.py

**Задача:** привести все числа к одному масштабу.

> **Зачем?** Без нормализации нейросеть "видит" только цену (40,000) и игнорирует RSI (65) — потому что 40,000 >> 65 по абсолютному значению. После нормализации все фичи примерно в диапазоне [-3, +3] и нейросеть воспринимает их одинаково важными.

> **Rolling (скользящая) нормализация** — вычисляем среднее и стандартное отклонение только по последним 30 дням, а не по всему датасету. Почему?
> **Data leakage (утечка данных из будущего):** если нормализовать глобально (по всем данным), то при обработке января 2020 года мы использовали бы среднее за 2024 год — а в реальности в 2020-м мы не знали как будет вести себя рынок в 2024-м.

```python
# строки 16–17
rolling_mean = df.rolling(window=window, min_periods=1).mean()
rolling_std = df.rolling(window=window, min_periods=1).std().replace(0, 1)
```

> `min_periods=1` = для первых дней (где нет 30 точек) используем сколько есть.

## 10. src/features/embedding_compressor.py

**Задача:** сжать вектор 384 → 32 числа через **PCA** (Principal Component Analysis — метод главных компонент).

> **Зачем сжимать?** 384 × 30 дней = 11,520 дополнительных входов для нейросети. Это медленно обучается и вызывает **переобучение** (overfitting — модель "зазубривает" тренировочные данные и плохо работает на новых).
> PCA находит 32 главных "направления разброса" в 384-мерном пространстве и сохраняет ~80-85% полезной информации.

```python
# строки 15–18
def __init__(self, input_dim: int = 384, output_dim: int = 32):
    self.input_dim = input_dim
    self.output_dim = output_dim
    self._pca = PCA(n_components=output_dim)
```

> Создаём PCA с 32 компонентами. Пока не обучен — просто объект sklearn.

```python
# строки 20–35
def fit(self, embeddings: np.ndarray):
    assert embeddings.shape[1] == self.input_dim
    # Проверяем что входная размерность правильная
    self._pca.fit(embeddings)
    # PCA находит 32 главных направления разброса в 384-мерном пространстве
    logger.info(f"explained variance: {self.explained_variance_ratio():.3f}")
    return self
```

> **Важно:** PCA **обучается (fit)** только на тренировочных данных (2020-2023), а не на тестовых (2024).
> Нельзя обучать на всём датасете — это data leakage: тогда при обработке 2020 года PCA уже "знало" бы как выглядят новости 2024 года.

```python
# строки 37–46
def transform(self, embeddings: np.ndarray) -> np.ndarray:
    return self._pca.transform(embeddings).astype(np.float32)
    # Проецируем (N, 384) → (N, 32)
```

```python
# строки 48–50
def explained_variance_ratio(self) -> float:
    return float(np.sum(self._pca.explained_variance_ratio_))
    # Сколько информации сохранено? Например: 0.82 = 82%
```

#### Логарифмическая доходность

```python
# строки 51–53
price_current = self.prices[self.current_step - 1]   # цена ВЧЕРА
price_next = self.prices[self.current_step]           # цена СЕГОДНЯ
log_return = float(np.log(price_next / price_current))
```

> Агент принял решение вчера вечером. Сегодня смотрим что получилось.
>
> **Формула:**
> ```
> log_return = ln(цена_сегодня / цена_вчера)
> ```
>
> **Числовой пример:**
> ```
> Вчера BTC стоил 40 000$, сегодня 41 000$
> log_return = ln(41000 / 40000) = ln(1.025) ≈ +0.0247  (рост ~2.5%)
>
> Вчера BTC стоил 40 000$, сегодня 38 000$
> log_return = ln(38000 / 40000) = ln(0.95) ≈ -0.0513   (падение ~5%)
> ```
>
> **Почему логарифм, а не просто процент?**
> - Обычные проценты нельзя складывать: +10% затем -10% ≠ 0% (реально -1%)
> - Логарифмы можно: `ln(p3/p1) = ln(p2/p1) + ln(p3/p2)` — это математически корректно
> - Симметричны: рост в 2 раза = `ln(2) ≈ +0.69`, падение в 2 раза = `ln(0.5) ≈ -0.69` (одинаковы по модулю)
> - Ближе к нормальному распределению — удобно для статистики

---

#### Формула награды (reward)

```python
# строки 55–56
tx_penalty = self.tx_cost * abs(allocation - self.prev_allocation)
reward = float(log_return * allocation - tx_penalty)
```

> **Полная формула:**
> ```
> reward = log_return × allocation  −  tx_cost × |allocation − prev_allocation|
>    [заработок]                         [штраф за смену позиции]
> ```
>
> **Разбор по частям:**
>
> **Часть 1 — заработок:** `log_return × allocation`
> ```
> BTC вырос на 2.5%  (log_return = +0.025),  вложено 80%  (allocation = 0.8)
> заработок = 0.025 × 0.8 = +0.020  (агент заработал 2% от капитала)
>
> BTC упал на 5%  (log_return = -0.05),  вложено 80%  (allocation = 0.8)
> заработок = -0.05 × 0.8 = -0.040  (агент потерял 4% от капитала)
>
> BTC упал на 5%  (log_return = -0.05),  вложено 0%  (allocation = 0.0)
> заработок = -0.05 × 0.0 = 0.0  (агент в кэше — убытка нет)
> ```
>
> **Часть 2 — штраф за сделку:** `tx_cost × |allocation − prev_allocation|`
> ```
> tx_cost = 0.001 (0.1% комиссия биржи)
>
> Был 0% → стал 80%:  штраф = 0.001 × |0.8 − 0.0| = 0.0008
> Был 80% → стал 80%: штраф = 0.001 × |0.8 − 0.8| = 0.0  (позиция не менялась — бесплатно)
> Был 80% → стал 0%:  штраф = 0.001 × |0.0 − 0.8| = 0.0008
> ```
>
> **Зачем штраф?** Без него агент мог бы каждый день менять позицию: 0% → 100% → 0% → ...
> В реальной торговле каждая сделка стоит денег. Штраф учит агента держать позицию и не "суетиться".
>
> **Итоговый пример одного дня:**
> ```
> BTC вырос +2.5%, агент вложил 80%, до этого был 0%
> reward = 0.025 × 0.8  −  0.001 × |0.8 − 0.0|
>        = 0.020         −  0.0008
>        = +0.0192
> ```

```python
# строка 61
terminated = self.current_step >= len(self.prices) - 1
```

> Эпизод заканчивается когда дошли до последнего дня.
> SB3 автоматически вызовет `reset()` и начнёт заново.

n_steps: int = 2048           # шагов агента перед одним обновлением весов
batch_size: int = 64          # размер мини-батча для градиентного спуска
n_epochs: int = 10            # сколько раз пройти по 2048 шагам
gamma: float = 0.99           # дисконт будущих наград

> `learning_rate = 3e-4` (= 0.0003) — **скорость обучения**: насколько сильно меняем веса нейросети за один шаг. Слишком большой → нестабильно, "прыгаем" мимо решения. Слишком маленький → обучаемся вечно.
>
> `n_steps = 2048` — сколько шагов (дней) агент играет прежде чем обновить веса нейросети. Больше → стабильнее оценка, но дольше.
>

>
> `n_epochs = 10` — сколько раз "пересматриваем" собранные 2048 шагов при обновлении. PPO может учиться на одних данных несколько раз (в отличие от A2C).
>
> `gamma = 0.99` — **дисконт-фактор**: насколько важны будущие награды. `0.99^100 ≈ 37%` → награда через 100 дней стоит только 37% от сегодняшней. Близко к 1 = агент думает о далёком будущем.
>
> `gae_lambda = 0.95` — параметр **GAE** (Generalized Advantage Estimation — обобщённая оценка преимущества): λ балансирует между точностью оценки (bias) и её стабильностью (variance).
>
> `clip_range = 0.2` — **главная идея PPO**: не позволяем policy (стратегии) измениться больше чем на ±20% за один шаг. Предотвращает "катастрофическое обновление" когда новая стратегия хуже старой.

### Обучение

```python
# строка 78
model.learn(total_timesteps=config.total_timesteps)
```

> **Вся магия в одной строке.** SB3 внутри запускает полный цикл обучения — снова и снова:
>
> ```
> ┌─────────────────────────────────────────────────────────────────┐
> │  1. reset()  → начальное состояние (день 30)                    │
> │  2. predict(obs) → нейросеть выдаёт allocation [0..1]           │
> │  3. step(action) → среда считает reward и новое obs             │
> │  4. повторяем 2-3 ещё 2047 раз  (n_steps = 2048)                │
> │  5. GAE: оцениваем насколько каждое действие было удачным        │
> │  6. PPO update: обновляем веса нейросети 10 раз (n_epochs=10)   │
> │  7. выбрасываем этот опыт, возвращаемся к шагу 1                │
> └─────────────────────────────────────────────────────────────────┘
> ```
>
> `total_timesteps = 500_000` = 500 тысяч вызовов `step()` = примерно **244 прохода** через весь год данных (2048 дней × 244 ≈ 500k).
>
> **GAE (Generalized Advantage Estimation — обобщённая оценка преимущества):**
> После каждых 2048 шагов нужно понять — насколько хорошим было каждое действие?
> Не просто "получил +0.02 награды", а "получил на X больше/меньше чем ожидалось".
> Это и есть **advantage** (преимущество): `advantage = реальная награда − ожидаемая награда`.
> Если advantage > 0 → действие было лучше ожидаемого → делаем его чаще.
> Если advantage < 0 → хуже ожидаемого → делаем реже.
>
> **Clip в PPO:**
> PPO не позволяет стратегии измениться слишком сильно за один шаг (`clip_range = 0.2`).
> Зачем? Слишком большое обновление может "сломать" то что агент уже выучил.
> PPO обрезает: если новая стратегия отличается от старой более чем на ±20% — игнорируем лишнее.

### Разные параметры для разных алгоритмов

```python
# строки 92–112
def _algo_specific_kwargs(config):
    if config.algorithm == "PPO":
        return {
            "n_steps": ..., "batch_size": ..., "n_epochs": ...,
            "gamma": ..., "gae_lambda": ..., "clip_range": ...,
        }
    elif config.algorithm == "A2C":
        return {"n_steps": ..., "gamma": ..., "gae_lambda": ...}
        # Нет batch_size/n_epochs — A2C обновляется на всём батче сразу
        # Нет clip_range — A2C не использует PPO clipping
    elif config.algorithm == "SAC":
        return {"gamma": ..., "batch_size": ...}
        # Off-policy: нет n_steps/gae_lambda (SAC использует replay buffer)
```

> **Почему у алгоритмов разные параметры?**
>
> **On-policy** (PPO, A2C) — учимся только на свежем опыте:
> ```
> Собрали 2048 шагов → обновили веса → выбросили опыт → собираем заново
> ```
> Поэтому нужен `n_steps` (сколько шагов собрать) и `gae_lambda` (как считать advantage).
>
> **Off-policy** (SAC) — используем **replay buffer** (буфер воспроизведения):
> ```
> Каждый шаг сохраняется в буфер (размером ~1 млн шагов)
> Для каждого обновления берём случайный mini-batch из буфера
> Старый опыт используется снова и снова
> ```
> Поэтому `n_steps` не нужен (учится после каждого шага), `gae_lambda` не нужен (у SAC другой способ оценки).
>
> **Итог:** PPO надёжнее и проще настраивается. SAC эффективнее по данным но сложнее. Поэтому в ablation study основной — PPO.

## 16. src/eval/metrics.py

**Задача:** посчитать финансовые метрики результата торговли.

```python
# строка 7
TRADING_DAYS_PER_YEAR = 365
```

> Крипта торгуется каждый день. Акции — 252 дня (без выходных).

```python

total_return = float(np.prod(1 + returns) - 1)
```

> `np.prod` = перемножение: `(1+r1) × (1+r2) × ... × (1+rn) - 1`.
> Пример: `[+5%, +10%, -3%]` → `1.05 × 1.10 × 0.97 - 1 = 0.1205` = +12.05%.

```python
# строки 23–27
mean_r = np.mean(returns)
std_r = np.std(returns, ddof=1)
sharpe_ratio = (mean_r / std_r) * np.sqrt(TRADING_DAYS_PER_YEAR)
```

> **Sharpe ratio** = (средняя дневная доходность / стандартное отклонение) × √365.
> Умножаем на √365 чтобы пересчитать дневную метрику в **годовую** (аннуализировать).
> `ddof=1` = делим на (n-1) вместо n — **поправка Бесселя** для выборочной дисперсии (уменьшает смещение оценки).
> Интерпретация: < 0 плохо (теряем деньги), 0–1 посредственно, 1–2 хорошо, > 2 отлично.

```python
# строки 29–33
downside = returns[returns < 0]
downside_std = float(np.std(downside, ddof=1))
sortino_ratio = (mean_r / downside_std) * np.sqrt(365)
```

> **Sortino** = как Sharpe, но штрафует только за **убыточную** волатильность.
> Sharpe штрафует за любую — в т.ч. прибыльную (несправедливо).

```python
# строки 35–38
cumulative = np.cumprod(1 + returns)
running_max = np.maximum.accumulate(cumulative)
drawdowns = 1 - cumulative / running_max
max_drawdown = float(np.max(drawdowns))
```

> `np.maximum.accumulate` = нарастающий максимум (каждый элемент = максимум из всех предыдущих).
> `drawdowns` = насколько упали от пика в каждый момент.
> **MDD (Max Drawdown / максимальная просадка)** — самое большое падение от пика до дна за всё время.
> MDD = 30% → "в худший момент портфель упал на 30% от своего исторического максимума".

```python
# строки 40–41
annual_return = (1 + total_return) ** (365 / len(returns)) - 1
calmar_ratio = annual_return / max_drawdown
```

> **Calmar** = годовая доходность / максимальная просадка.
> Calmar > 1 → зарабатываешь больше чем максимально рискуешь.

## 18. src/eval/bootstrap.py

**Задача:** статистически доказать что разница между агентами не случайная.

> **Проблема:** RL зависит от **random seed** (начального значения генератора случайных чисел). Нейросеть инициализируется случайно, и разные начальные веса могут дать разные результаты. Один запуск PPO может дать Sharpe = 1.5, другой — 0.8.
> Как доказать что Agent-2 **действительно лучше** Agent-1, а не просто "повезло с seed"?

```python
# строка 29
rng = np.random.RandomState(seed)
```

> Генератор случайных чисел с фиксированным seed.
> Результаты воспроизводимы — одинаковые при каждом запуске.

```python
# строки 32–33
seed_metrics = [compute_metrics(r) for r in returns_list]
metric_names = ["sharpe_ratio", "total_return"]
```

> Считаем метрики для каждого seed отдельно.
> `returns_list` = список массивов, один на seed.

```python
# строки 37–45
values = np.array([m[metric] for m in seed_metrics])
# values = [1.2, 0.8, 1.5, 1.1, 0.9] (5 seeds)

boot_means = np.empty(n_bootstrap)
for i in range(n_bootstrap):   # 5000 раз:
    sample = rng.choice(values, size=len(values), replace=True)
    # Берём случайные len(values) элементов С ПОВТОРЕНИЯМИ
    # Из [1.2, 0.8, 1.5, 1.1, 0.9] → [1.2, 1.2, 0.9, 1.5, 1.1]
    boot_means[i] = np.mean(sample)
```

> **Bootstrap** — метод статистики: многократно берём случайные выборки из имеющихся данных с повторениями (`replace=True`), считаем среднее каждый раз. Получаем 5000 вариантов среднего → видим его распределение.
> Это позволяет оценить погрешность даже когда данных мало (всего 5 seeds).

```python
# строки 47–49
alpha = (1 - confidence) / 2         # 0.025
ci_lower = float(np.percentile(boot_means, alpha * 100))    # 2.5-й перцентиль
ci_upper = float(np.percentile(boot_means, (1-alpha) * 100)) # 97.5-й перцентиль
```

> Берём 2.5% и 97.5% перцентили → **95% доверительный интервал**.

> **Интерпретация результата:**
> ```
> Agent-1 Sharpe CI: [0.5, 1.0]

result = run_backtest(
