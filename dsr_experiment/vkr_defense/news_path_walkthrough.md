# Как работает система: путь новости и живой дашборд

> Разбор кода для защиты ВКR. Документ написан так, чтобы его можно было зачитывать вслух:
> каждый шаг сначала объясняется простыми словами («что и зачем»), и только потом даётся
> точная ссылка на файл и функцию в коде.

**Тема:** торговый агент на BTC/USDT, который принимает решения «купить / держать / продать»
на основе цены **и** новостного фона. Новости проходят через две нейросети
(FinBERT — тональность, FinLang — смысл), сжимаются и подаются обученному агенту
(Reinforcement Learning) вместе с ценовыми индикаторами.

# Часть I. Путь одной новости

## Общая схема

```
   Новостной датасет (HuggingFace: edaschau/bitcoin_news)
        │
        ▼
   [1] Загрузка и фильтрация по датам        →  таблица: [текст, дата]
        │
        ▼
   [2] Группировка в 4-часовые окна          →  {окно → список текстов}
        │
        ├──► [3] FinBERT      каждый текст → тональность  ∈ [−1, +1]
        │
        └──► [4] FinLang      каждый текст → смысловой вектор (768 чисел)
                   │
                   ├─ [5] PCA обучается на ВСЕХ обучающих векторах   →  сжатие 768 → 32
                   │
                   └─ [6] векторы окна взвешиваются по тональности,
                          усредняются и сжимаются                     →  32 числа (emb_0…emb_31)
        │
        ▼
   [7] В строку окна пишутся:  sentiment_mean  +  emb_0…emb_31   (33 «новостных» признака)
        склейка с 8 ценовыми индикаторами                         →  41 признак  →  features.parquet
        │
        ▼
   [8] Загрузка: таблица → матрица признаков + отдельный сигнал тональности
        │
        ▼
   [9] Окно из 30 строк = наблюдение агента (1231 число)
        тональность дополнительно входит в награду (sentiment-бонус)
```

Дальше — каждый шаг подробно.

---

## Шаг 1. Загрузка новостей

**Простыми словами.** Берём готовый открытый датасет биткойн-новостей с HuggingFace,
приводим даты к единому часовому поясу (UTC), убираем дубликаты по заголовку и оставляем
только новости из нужного периода (обучающего или тестового).

**Зачем.** Нужна чистая таблица «текст + дата», синхронизированная по времени с ценами.

**Где в коде:** `lib/features/news.py` → `load_news_from_hf()`.
Ключевые места: приведение даты — `pd.to_datetime(..., utc=True)`; фильтр по периоду —
сравнение `date` с границами `start`/`end`.

---

## Шаг 2. Группировка в 4-часовые окна

**Простыми словами.** Цена у нас идёт 4-часовыми свечами. Чтобы новости «легли» на ту же
сетку времени, каждую новость округляем вниз до начала её 4-часового окна (00:00, 04:00,
08:00 …) и собираем все новости одного окна в один список.

**Зачем.** Агент принимает решение раз в 4 часа — значит, и новостной фон должен быть
агрегирован по тем же 4-часовым интервалам.

**Где в коде:** `lib/features/news.py` → `preprocess_news_4h()`.
Ключевое место: `df["date"].dt.floor("4h")` затем `groupby("date")`.

---

## Шаг 3. Тональность новости (FinBERT)

**Простыми словами.** Каждую новость прогоняем через **FinBERT** — нейросеть, специально
дообученную на финансовых текстах. Она говорит, новость позитивная, негативная или
нейтральная, и насколько уверена. Мы превращаем это в одно число от −1 (резко негативно)
до +1 (резко позитивно).

**Зачем.** Это «эмоциональный заряд» новости — насколько она хорошая или плохая для рынка.

**Где в коде:** `lib/features/sentiment.py` → `compute_sentiment_scores()`.
Модель — `ProsusAI/finbert`. Формула числа: `уверенность × знак метки`
(`positive → +`, `negative → −`, `neutral → 0`).

---

## Шаг 4. Смысл новости (FinLang-эмбеддинги)

**Простыми словами.** Параллельно каждую новость прогоняем через вторую модель —
**FinLang** (sentence-transformer для финансов). Она превращает текст в вектор из 768 чисел,
который кодирует **о чём** новость (тема, контекст), а не только её тональность.

**Зачем.** Тональность отвечает на вопрос «насколько хорошо/плохо», а эмбеддинг — «о чём
вообще речь». Два разных среза информации.

**Где в коде:** `lib/features/embeddings.py` → `_get_model()` (загрузка модели
`FinLang/finance-embeddings-investopedia`) и вызов `model.encode(texts)` → матрица
`(число новостей, 768)`.

---

## Шаг 5. Обучение сжатия (PCA — только на обучающих данных)

**Простыми словами.** 768 чисел на новость — это слишком много и шумно. Мы обучаем
**PCA** (метод главных компонент) находить 32 самых информативных направления и сжимать
768 → 32. **Важно:** PCA обучается строго на обучающем периоде, а затем этим же
сжатием обрабатываются тестовые новости.

**Зачем.** Меньше признаков → агент учится быстрее и меньше переобучается. А обучение PCA
только на train — это гарантия, что в тест не «протекает» информация из будущего.

**Где в коде:** `build_data.py` → `build_train()` собирает все обучающие эмбеддинги и
вызывает `EmbeddingCompressor.fit()` (`lib/features/embeddings.py`). Результат сохраняется в
`data/train/compressor.pkl` и переиспользуется для тестовых периодов в `build_oos()`.

---

## Шаг 6. Взвешивание по тональности и сжатие

**Простыми словами.** В одном 4-часовом окне обычно несколько новостей. Мы объединяем их
смысловые векторы в один, но **не простым средним**: новости с сильной тональностью
(очень позитивные или очень негативные) получают больший вес, нейтральные — меньший.
Полученный единый 768-вектор сжимаем через обученный PCA в 32 числа.

**Зачем.** Важные (эмоционально заряженные) новости должны сильнее влиять на «смысл окна»,
чем проходные нейтральные сообщения.

**Где в коде:** `build_data.py` → `_attach_nlp_features_minimal()`.
Веса: `w = тональность + знак(тональности)·0.1`, нормировка на сумму модулей;
итог — `compressor.transform(взвешенное_среднее)` → `emb_0 … emb_31`.

---

## Шаг 7. Сборка таблицы признаков (41 признак)

**Простыми словами.** Теперь складываем всё, что агент будет «видеть» на каждом шаге:

| Группа | Сколько | Что это |
|---|---|---|
| Ценовые индикаторы | **8** | EMA-26, MACD, RSI-14, ширина Bollinger, ATR-14, OBV, Stoch %K, дневная доходность |
| Тональность | **1** | `sentiment_mean` — средняя тональность окна |
| Смысл новостей | **32** | `emb_0 … emb_31` — сжатый смысловой вектор |
| **Итого** | **41** | один набор признаков на каждое 4-часовое окно |

Ценовые индикаторы нормализуются скользящим z-score (окно 30 баров). Всё это пишется в
один файл `features.parquet` — по строке на 4-часовое окно.

**Зачем именно 8 + 1 + 32.** Это сознательно компактный набор: по литературе (FinRL,
SAPPO) большего обычно и не нужно, а меньше признаков = понятнее и устойчивее.

**Где в коде:** `build_data.py` → `_build_baseline()` (индикаторы + нормализация) и
`_attach_nlp_features_minimal()` (новостные признаки).

---

## Шаг 8. Загрузка признаков в модель

**Простыми словами.** При обучении и тесте читаем `features.parquet` и разделяем его на три
части: реальные цены (для подсчёта прибыли), матрицу из 41 признака (это «глаза» агента) и
отдельно сигнал тональности (он понадобится в награде).

**Зачем.** Цены нужны для честного P&L; признаки — для решений; тональность — и для решений,
и для подсказки в награде.

**Где в коде:** `lib/data_loader.py` → `load_train()` / `load_oos()`.
Реальные цены — колонка `raw_close`; сигнал — колонка `sentiment_mean`.
Режим `--no-news` зануляет все новостные признаки и сигнал — это аблация «с новостями / без».

---

## Шаг 9. Наблюдение агента и награда

**Простыми словами.** На каждом шаге агент видит **последние 30 окон** (≈5 дней) по 41
признаку плюс свою текущую долю в BTC — итого 1231 число. Это его «наблюдение».
Он выбирает действие:

- **DQN** — дискретно: держать / купить всё / продать всё;
- **SAC** — непрерывно: какую долю капитала (0–100%) держать в BTC.

Награда — это **DSR** (дифференциальный коэффициент Шарпа: вознаграждает рост доходности
с поправкой на риск) плюс **sentiment-бонус**: если тональность новостей совпала с
направлением движения цены — небольшая добавка. Из награды вычитается комиссия за изменение
позиции.

**Зачем sentiment-бонус.** Так новости влияют на агента **дважды**: и как вход (смысл +
тональность), и как форма награды — это подталкивает агента учитывать новостной фон.

**Где в коде:** `lib/env.py` → `_get_obs()` (формирование наблюдения) и `step()`
(награда: `DSR(R) + λ·тональность·доходность`, где λ = 0.3).

---

## Почему это честно: нет «подглядывания в будущее»

Это главный вопрос любого рецензента к торговым системам. У нас две защиты:

1. **Нормализация строго «в прошлое».** Скользящий z-score на шаге *t* использует только
   окно `[t−29, t]` — никаких будущих баров (`lib/features/price.py` →
   `rolling_zscore_normalize`).
2. **PCA обучается только на train** и применяется к тесту без переобучения
   (`build_data.py`, шаг 5).

Значит, на каждом решении агент опирается только на информацию, которая реально была
доступна в тот момент. Никакой утечки из будущего.

# Часть II. Дашборд

**Что это.** Streamlit-приложение для живой демонстрации: оно подтягивает свежие
BTC-новости, прогоняет их через тот же конвейер (FinBERT → FinLang → сжатие → признаки),
опрашивает ансамбль из 10 обученных сетей и показывает решение **BUY / HOLD / SELL**
прямо сейчас.

## Архитектура

- **`dashboard/app.py`** — лендинг: сводка по сохранённым результатам (лучший Sharpe,
  сколько моделей прибыльны) и навигация на три раздела.
- **`pages/1_Strategy.py`** — «Решение прямо сейчас»: свежие новости, текущее решение
  ансамбля, цена BTC и история за последние дни.
- **`pages/2_Validation.py`** — «Валидация на истории»: прогон на 2024 и 2025, сравнение с
  Buy & Hold, equity-кривые.
- **`pages/3_News_Analyzer.py`** — «Анализатор новости»: вставляешь любой текст и видишь,
  как меняется голосование ансамбля.

## Как принимается решение в реальном времени

1. **Свежие новости.** Если лента старше 4 часов — приложение тянет новые BTC-новости и
   считает их тональность FinBERT (`pages/1_Strategy.py`, блок автообновления).
2. **Те же признаки, что при обучении.** Для каждого 4-часового окна строится ровно такой
   же набор признаков, как в обучении: индикаторы + тональность + сжатый эмбеддинг
   (`dashboard/utils/feed_decisions.py` → `_build_features`). Наблюдение собирается точно как
   в среде: последние 30 строк + текущая доля.
3. **Голосование ансамбля.** Наблюдение прогоняется через все 10 сетей
   (`_run_ensemble`). Для **DQN** — большинство голосов BUY/HOLD/SELL определяет действие
   (всё или ничего); для **SAC** — итоговая доля = медиана непрерывных голосов.
4. **Показ.** Большой бейдж решения, распределение голосов, заголовки новостей окна, графики
   цены и доходности против Buy & Hold.

## Связь с обучением

Ключевой принцип: дашборд **повторяет обучающий конвейер один-в-один** — те же модели те же
признаки, та же сборка наблюдения. Поэтому обученная сеть применяется к «живым» данным без
какого-либо дообучения — это и делает демонстрацию убедительной.

# Словарь терминов

| Термин | Простое объяснение |
|---|---|
| **RL / агент** | Reinforcement Learning — обучение методом проб и ошибок; «агент» учится действиям, максимизирующим награду. |
| **DQN** | RL-алгоритм с дискретными действиями (держать / купить / продать). Хорошо подходит для одного актива и небольших данных. |
| **SAC** | RL-алгоритм с непрерывными действиями (любая доля 0–100%). |
| **FinBERT** | Нейросеть, дообученная на финансовых текстах; выдаёт тональность новости. |
| **FinLang-эмбеддинг** | Вектор из 768 чисел, кодирующий смысл текста. |
| **PCA** | Метод главных компонент; сжимает много признаков в несколько информативных. |
| **DSR** | Дифференциальный коэффициент Шарпа — награда, поощряющая доходность с поправкой на риск. |
| **sentiment-бонус** | Добавка к награде, когда тональность совпадает с движением цены. |
| **аллокация** | Доля капитала, вложенная в BTC (0% = всё в деньгах, 100% = всё в BTC). |
| **OOS** | Out-of-sample — тестовый период, не виденный при обучении. |
| **ансамбль** | Несколько моделей (10 сидов), решающих вместе; голосование снижает случайность. |
| **Buy & Hold** | Наивная стратегия «купил и держишь» — базовый ориентир для сравнения. |
